# SHA3-256 на C

Программа вычисляет SHA3-256 содержимого файла. Алгоритм написан на C11 по [FIPS 202](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.202.pdf), без криптографических библиотек. Требования задания находятся в [TASK.md](TASK.md).

Подробное объяснение алгоритма, каждой непустой строки кода, сборки, тестов и мер безопасности: [extended.md](extended.md).

## Функциональность

- Принимает путь к одному файлу, читает его в бинарном режиме и выводит хеш из 64 шестнадцатеричных символов вместе с именем файла.
- Обрабатывает пустые, текстовые и бинарные файлы, включая файлы больше 1 МБ.
- При ошибке открытия, чтения или записи завершает работу с ненулевым кодом и сообщением в stderr.

## Запуск

Нужны компилятор C11 (GCC или Clang) и GNU Make. Для тестов дополнительно нужны Python 3.9+ и OpenSSL с SHA3-256.

1. Соберите программу:

   ```sh
   make
   ```

2. Передайте файл:

   ```sh
   ./build/sha3sum TASK.md
   ```

Путь с пробелами заключайте в кавычки. Программа принимает именно путь к файлу, строка `-` считается именем файла. Код выхода: `0` при успехе, `1` при ошибке.

Очистка сборки: `make clean`. Тестовые данные сохраняются.

## Стек

- C11 и стандартная библиотека C для программы.
- Makefile для сборки и запуска проверок.
- Python и OpenSSL для проверки результата.

## Технические решения

В [src/sha3.c](src/sha3.c) реализована конструкция sponge: состояние из 25 слов по 64 бита, блок поглощения 136 байт и перестановка Keccak-f[1600] из 24 раундов. Раунд выполняет шаги theta, rho, pi, chi и iota. После поглощения данных добавляются суффикс SHA-3 и padding (`0x06`, нули, `0x80`), затем извлекаются 32 байта хеша. При одном свободном байте padding равен `0x86`.

[src/main.c](src/main.c) отвечает за аргументы, открытие файла и вывод. Контракт файловой хеш-функции описан в [src/sha3.h](src/sha3.h). В коде есть пояснения алгоритма и комментарии `SECURITY` рядом с решениями, связанными с безопасностью:

- Буфер чтения имеет размер 8192 байта, память программы не растёт с размером файла. Индекс внутри блока ограничен 136 байтами; общий размер файла не суммируется, поэтому счётчик длины не переполняется.
- Явная упаковка байтов исключает невыровненные обращения, нарушение strict aliasing и зависимость от порядка байт процессора.
- Поворот на ноль обрабатывается отдельно, чтобы исключить неопределённый сдвиг на 64 бита.
- Ошибки чтения проверяются до выдачи результата: хеш усечённого файла не выводится. Ошибка закрытия файла и ошибка буферизованной записи также приводят к отказу.
- Управляющие символы в именах файлов экранируются, форматные строки фиксированы. Это ограничивает подделку вывода и обработку имени как форматной строки.

Файл должен оставаться неизменным во время чтения: программа хеширует полученные байты и не создаёт снимок файла. Обычный хеш позволяет проверить целостность относительно доверенного эталона, но сам по себе не подтверждает автора файла.

## Тестирование

```sh
make test
make sanitize
make demo
```

`make test` проверяет известные векторы (пустое сообщение, `abc`, миллион символов `a`), все остатки длины блока, границы буфера чтения, случайные бинарные файлы и файл размером 2 МБ + 17 байт. Каждый хеш сравнивается с OpenSSL и `hashlib.sha3_256`. Проверяются также ошибки аргументов, отсутствующий файл, ошибка чтения каталога, управляющие символы в имени и ошибка записи через `/dev/full`. Проверки каталога и специальных имён предназначены для POSIX; `/dev/full` проверяется при его наличии.

`make sanitize` запускает те же проверки со сборкой AddressSanitizer и UndefinedBehaviorSanitizer (нужна поддержка этих инструментов компилятором).

Если среда выполняет процессы под ptrace, LeakSanitizer не может запуститься. Для такой среды используйте `ASAN_OPTIONS=detect_leaks=0 make sanitize`: проверки обращений к памяти и неопределённого поведения остаются включены, проверка утечек отключается.

`make demo` создаёт [examples/small.txt](examples/small.txt) с тремя байтами `abc` и [examples/large.bin](examples/large.bin) размером 2 097 152 байта. Большой файл содержит последовательность байтов 0..255, повторённую 8192 раза. Скрипт выводит хеши программы и OpenSSL и итог сравнения прямо в терминал, поэтому его можно использовать при личной сдаче.

Проверено: сборка GCC без предупреждений, `make test` (8 групп, 171 сравнение хешей), `ASAN_OPTIONS=detect_leaks=0 make sanitize` и совпадение обеих демонстраций с OpenSSL. Проверка утечек в этой среде не запускалась из-за ограничения ptrace.

Эти проверки не заменяют сертификацию криптографической реализации.
